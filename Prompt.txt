7. REAL WINDOWS DISPLAY CONTROL
============================================================

THIS IS ONE OF THE MOST IMPORTANT REQUIREMENTS.

Do NOT fake brightness or temperature changes by simply changing
the CSS of the Eyes Care window.

Eyes Care must control the actual Windows display environment.

Implement a native Display Control Engine.

Architecture:

Electron
    ↓
Node.js
    ↓
Secure IPC
    ↓
Display Manager
    ↓
Windows Native Layer

The implementation must support multiple methods depending on the
hardware:

1. Windows display APIs
2. DDC/CI where supported
3. Gamma ramp/color LUT where appropriate
4. Software color/filter overlay as fallback where hardware control
   is unavailable

The application must detect capabilities.

For example:

Monitor supports hardware brightness:
    → use hardware brightness

Monitor does not support hardware brightness:
    → use supported software/gamma approach

Color temperature may require gamma/color LUT transformation.

DO NOT claim that all monitors support hardware temperature control.

Build a capability detection system.

Example:

Monitor 1:
Hardware Brightness: YES
DDC/CI: YES
Gamma Control: YES

Monitor 2:
Hardware Brightness: NO
DDC/CI: NO
Gamma Control: YES

The UI should adapt accordingly.
